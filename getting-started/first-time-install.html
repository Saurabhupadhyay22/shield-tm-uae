First-time install

This page installs Shield Astra from the release tarball onto a fresh Linux host. Total time: about one hour with all prerequisites ready.

Before you start

Make sure every item on the Prerequisites page is in hand — especially the Firebase credentials and (for production) the OpenSanctions commercial licence. Missing credentials block install.

1. Get the release tarball​

The Shield Astra release is delivered as a signed tarball via the vendor's release channel. If you don't have your access URL yet, contact releases@solutio.ae.

cd /opt
sudo mkdir -p omnis-tm && sudo chown $USER omnis-tm
cd omnis-tm

# Replace <RELEASE_URL> with the URL from the vendor
curl -fL <RELEASE_URL>/shield-tm-uae-v0.1.0.tar.gz -o release.tar.gz

# Verify the signature (details in the release email)
curl -fL <RELEASE_URL>/shield-tm-uae-v0.1.0.tar.gz.sig -o release.tar.gz.sig
gpg --verify release.tar.gz.sig release.tar.gz

# Extract
tar xzf release.tar.gz

You should now have a directory structure like:

/opt/omnis-tm/
├── docker-compose.yaml
├── installer/
│   ├── install.sh
│   ├── seed.sh
│   ├── verify.sh
│   ├── upgrade.sh
│   └── rollback.sh
├── config/
│   └── env.production.template
├── secrets/                    # empty; you populate this
├── compliance/                 # MSA, DPA, SBOM, DPIA templates
├── docs/                       # offline copy of this documentation
└── VERSION

2. Create your .env file​

Copy the template and fill in every CHANGE_ME_ value:

cp config/env.production.template .env
$EDITOR .env

The four fields you must fill in yourself:

  • OMNIS_APP_URL — the URL users will hit in a browser (e.g. https://tm.omnis-tm.ae or http://<vm-public-ip>:3100 for first-time internal testing)
  • PG_PASSWORD — generate with openssl rand -base64 24
  • SESSION_SECRET — generate with openssl rand -hex 32 (must be ≥ 32 chars)
  • MINIO_ROOT_PASSWORD — generate with openssl rand -base64 24

The rest are pre-filled or optional. See Administration › Environment variables for the complete reference.

3. Drop in the Firebase service account key​

Place the Firebase Admin SDK service account JSON at:

secrets/firebase-service-account.json

The installer refuses to boot the backend without this file present. See Configuring Firebase auth for the exact Firebase Console click-through if you haven't downloaded it yet.

4. Run the installer​

./installer/install.sh

The installer script:

  1. Checks Docker Engine and Compose versions
  2. Loads and validates .env values
  3. Loads the offline-installable image tars into your local Docker
  4. Runs Alembic database migrations
  5. Runs seed.sh which inserts the single organisation row + first admin user, and creates the per-org Postgres schema
  6. Brings up the full stack via docker compose up -d

Watch the output. Every step prints [OK] or [FAIL]. If any step fails, the installer prints the specific fix at the bottom of the output. Common first-run issues:

  • Port 3100 already in use → change FRONTEND_PORT in .env and re-run
  • Firebase auth error → check FIREBASE_PROJECT_ID matches the service account JSON's project_id field
  • PG connection refused → wait 20 seconds; Postgres takes a moment on first cold boot and the installer retries with backoff

Full install takes 5–10 minutes depending on disk speed. Yente is the slowest — it downloads the OpenSanctions dataset the first time (~8 minutes for sanctions-only, ~30 minutes for the full default set).

5. Verify the install​

Once the installer prints install complete, run the verifier:

./installer/verify.sh

This performs a smoke test:

  • Backend responds 200 on /liveness
  • Frontend serves /index.html
  • Postgres has the seed row
  • MinIO bucket omnis-case-manager exists
  • Yente responds 200 on /healthz
  • Continuous screening worker is registered
  • Every environment variable required by the running containers is set

Expected output ends with:

==> verify complete
    All checks passed. Shield Astra is ready to use.
    Frontend: http://<host>:3100
    Admin email: <the value of OMNIS_ADMIN_EMAIL from .env>

6. Log in for the first time​

Open the frontend URL in a browser. You'll be prompted for Firebase login.

Sign in with the email you set as OMNIS_ADMIN_EMAIL in .env. Firebase will send you a magic-link email — click it to complete first login.

Email verification workaround

If the verification email doesn't arrive (common in test environments where Firebase's own SMTP hasn't been configured), The vendor ships an ops utility to mark the email verified server-side:

docker exec omnis-backend python scripts/verify_firebase_email.py <your-email>

See Administration › Troubleshooting for more workarounds.

Once logged in, you're the first admin user. Next steps:

  • Setting up your first admin user — add other users, configure roles, create your first inbox
  • Post-install checklist — the 15-item checklist your DevOps hands to the compliance function
  • Scenarios & Rules › Executing a scenario — build your first monitoring scenario

Troubleshooting​

If any step of the install fails, see Administration › Troubleshooting or open a ticket with Support and escalation.
