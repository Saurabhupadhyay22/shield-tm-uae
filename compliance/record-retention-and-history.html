Record retention and history

Every table in Shield Astra keeps history. Nothing is deleted. Old versions live alongside the current one.

Why this page exists

The compliance officer's question "was this customer a PEP when this transaction happened?" has one right answer — and it's not "yes, they are now." Snapshot-only systems get this wrong. SCD-2 gets it right.

The SCD-2 shape​

Every row has six standard columns on top of its business columns:

ColumnTypeWhat it stores
iduuidUnique per version
object_idtextStable across versions (the real-world entity ID)
valid_fromtimestamptzWhen this version became current
valid_untiltimestamptzWhen it stopped ('infinity' = still current)
created_datetimestamptzWhen the entity first entered the system (immutable)
updated_attimestamptzWhen this version row was written

Constraint: UNIQUE(object_id, valid_from) — no two versions can start at the exact same instant.

History as a timeline​

A rule asking "was this customer a PEP at the time of this transaction?" picks the version whose [valid_from, valid_until) window covers the transaction's created_date.

What re-ingestion does​

Both statements share a transaction. Rollback on failure — no gap, no overlap, always consistent.

Reading the current version​

SELECT * FROM customer
WHERE object_id = 'cust_123'
  AND valid_until = 'infinity';

There's a convenience view customer_current that hides the filter. The rule engine, the Your Data page, and case-manager detail pages all default to current.

Reading history​

SELECT pep_status
FROM customer
WHERE object_id = 'cust_123'
  AND valid_from <= '2026-07-01T00:00:00Z'
  AND valid_until >  '2026-07-01T00:00:00Z';

Exactly one row matches. The engine does this for every linked-field lookup — see Fields and links → Historical links.

Deletions​

There is no DELETE /v1/ingestion/customer endpoint.

  • Offboard a customer
  • Correct an erroneous ingestion
  • Right-to-erasure (UAE PDPL)

Set is_active = false on the next ingestion. History stays.

POST /v1/ingestion/customer/<object_id>/correct

Closes the current version and inserts a new one flagged correction_reason. The wrong version is preserved for audit but excluded from "real historical state" queries.

Requires the DATA_PROTECTION_OFFICER role. Writes a tombstone to astra.data_erasure_events before physically removing the row versions.

See Compliance → Audit trail export.

Regulatory basis​

RuleWhat it requiresHow SCD-2 satisfies it
FATF R.115-year record retentionRows never deleted
CBUAE AML/CFT §65-year retention (LFI)Rows never deleted
VARA CRMR Part V8-year retention (VASP)Rows never deleted
UAE PDPL Art. 10Right to erasureErasure endpoint + tombstone

Storage cost​

For a mid-tier PSP: ~35 GB / year total across all 8 tables. Postgres gp3 storage ≈ $0.10 / GB / month = ~$42 / year to keep 100% of history forever.

Retention is functionally free. There is no reason to tune it.
