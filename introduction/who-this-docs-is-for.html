Who this documentation is for

Shield Astra has four categories of user, and the documentation is structured so each one has a clear on-ramp. Find yourself below and jump to your starting point.

The MLRO or Head of Compliance​

You are responsible for the licensee's AML programme. You need to understand:

  • What compliance surface Shield Astra covers and where the gaps are
  • Which regulatory obligations (CBUAE, VARA, FATF, goAML) the product discharges for you
  • How to demonstrate compliance during a CBUAE or VARA inspection
  • What third-party vendors and data providers are in the supply chain and their licensing status

Read in this order:

  1. What is Shield Astra — you are here already if you follow the sidebar
  2. UAE Regulatory Context — CBUAE, VARA, FATF R.6/10/12/15/16 mapping
  3. Compliance Runbooks › Overview — the daily runbooks your team will actually use
  4. Vendors & Integrations › Decision matrix — the full third-party supply chain

The compliance analyst​

You investigate alerts and file STR/SAR reports. You need:

  • The daily walkthrough of Case Manager — how to work an inbox, review a case, comment, escalate, close, set an outcome
  • How the AI Case Review button assists you (and its limits)
  • How to trigger a KYC Enrichment on a subject
  • How to search sanctions and PEP lists directly
  • Where to click to file an STR to goAML

Read in this order:

  1. Case Manager › Overview
  2. Case Manager › AI Case Review
  3. Continuous Screening › Ad-hoc Screening Search
  4. Compliance › UAE STR/SAR filing

The system administrator or DevOps engineer​

You install, upgrade, and operate Shield Astra. You need:

  • Install and post-install procedures
  • Every environment variable, what it does, what a safe default is
  • How to configure Firebase auth, OpenAI, Yente, ACS email
  • Backups, disaster recovery, upgrade procedures
  • Troubleshooting when something breaks in production
  • How to swap a third-party vendor (e.g., replace OpenAI with Azure OpenAI for data residency)

Read in this order:

  1. Getting Started › Prerequisites
  2. Getting Started › First-time install
  3. Administration › Overview
  4. Administration › Environment variables
  5. Administration › Backups and DR
  6. Vendors & Integrations › Swap guides

The developer or integration engineer​

You build data pipelines, custom rules, and integrations against Shield Astra. You need:

  • The data model, in detail — what tables, what fields, what links
  • The ingestion API for pushing transactions in
  • The full REST API for pulling decisions, cases, and screening results out
  • Rule authoring — the AST, aggregate rules, custom lists in rules
  • Webhooks for real-time integration

Read in this order:

  1. Data Model › Overview
  2. Data Model › Ingesting data
  3. Scenarios & Rules › Formula reference
  4. API Reference › Overview
  5. API Reference › Webhooks

The tester or product-quality reviewer​

You verify Shield Astra against a spec, either before rollout or during UAT. You need:

  • What features exist and roughly where each is documented
  • Sample data and test transactions to exercise each feature
  • A recipe for firing synthetic transactions to check the decisioning engine end-to-end
  • A checklist of expected outcomes per test

Read in this order:

  1. Product tour — one-video overview
  2. Getting Started › Post-install checklist
  3. Scenarios & Rules › Testing rules
  4. Rule Library › Overview — the full pre-built rule catalogue you can run tests against

Where the docs will grow next​

Right now (August 2026) the documentation is being written chapter by chapter. The Introduction and Getting Started chapters are ready; the Rule Library and Compliance Runbooks chapters are being written next. See Release Notes › Current for a live status page.
