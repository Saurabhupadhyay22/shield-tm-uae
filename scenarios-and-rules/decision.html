Decision

Every rule contributes points. The scenario sums them. The score band maps the total to one of four outcomes.

The four outcomes
  • Approve — pass through, no case
  • Review — pass through, create a case for later review
  • Block-and-Review — hold the payment, create a case now
  • Decline — reject the payment, create a case

The default bands​

Straight from the Fiat TM scenario's Decision tab — this is the actual widget compliance officers see:

BandScoreOutcomeWhat the core system does
00–9ApproveRelease the payment; no case
110–29ReviewRelease the payment; case in inbox for later
230–49Block-and-ReviewHold the payment; case created now, waits for analyst
350+DeclineReject the payment; case created

Where bands live​

Scenarios → open scenario → Score thresholds. Editable — but governance matters. Changing thresholds shifts the risk / operations tradeoff of the whole scenario.

Tuning trade-offs​

  • Tighter thresholds (lower band boundaries)
  • Looser thresholds (higher band boundaries)
  • Better: tune the rules, not the thresholds

Effect: More transactions land in Review, Block-and-Review, Decline.

Pros: Catches more risk. Cons: More false positives, more analyst work, more customer friction.

When: Regulator inspection is imminent, or a recent case surfaced a rule gap.

Effect: Fewer transactions escalated.

Pros: Lower analyst load, less customer friction. Cons: Real risk may slip through into Approve.

When: False-positive rate is high and traceable to specific rules that need re-weighting instead.

Thresholds are the last resort. If a false-positive rate is high:

  1. Find the offending rule via Analytics → Rule performance
  2. Duplicate it, adjust its weight or condition
  3. Test the new iteration (Testing rules)
  4. Publish

Leave the bands alone.

Bespoke bands​

Not every business needs four outcomes. Configurations you can pick from:

ConfigurationBandsUse case
Default4 (Approve / Review / Block-and-Review / Decline)Most PSPs and VASPs
3-bandApprove / Review / Decline (no block-and-review)Businesses without a hold-payment capability
2-bandApprove / Case onlyAdvisory monitoring — you never hold payments
CustomRename any bandE.g. "Approve" → "Auto-clear" for internal wording

Multi-scenario aggregation​

If a table has more than one scenario (Scenario triggers → Priority), each produces its own score + outcome. The workflow layer picks the worst outcome across all scenarios by default:

What the ingestion API returns​

{
  "status": "ok",
  "decision": {
    "outcome": "Block-and-Review",
    "score": 25,
    "band": "block_and_review",
    "scenario": "Fiat Transaction Monitoring — v3.2",
    "rules_fired": [
      {"name": "Very-large cross-border transfer", "score": 10},
      {"name": "FATF Increased Monitoring receiver country", "score": 10},
      {"name": "CBUAE FTS reporting threshold", "score": 5}
    ],
    "case_id": "case_2026_08_17_042"
  }
}

The core system reads decision.outcome — everything else is for audit and case-manager display.
